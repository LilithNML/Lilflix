# Lilflix\n\nSPA estática de Svelte + Vite + TypeScript.\n\n## Desarrollo\n\n```bash\nnpm install\nnpm run dev\n```\n\nAntes de `dev`/`build`, el sync obtiene de AniList los metadatos que falten y los guarda en `src/content/generated/media.json`.\n\n## Comandos\n\n- `npm run dev` — desarrollo.\n- `npm run build` — sync + build de producción.\n- `npm run typecheck` — comprobación TypeScript.\n- `npm test` — tests de validación.\n- `npm run sync` — sincronización incremental.\n- `npm run sync -- --refresh` — renueva todos los IDs.\n- `npm run sync -- --id 21` — renueva un ID concreto.\n\n## Añadir contenido\n\nEdita únicamente `src/content/catalog.ts`. Usa `series({ anilistId, episodes })` para una temporada o `series({ anilistId, seasons })` para varias. Para una película usa `movie({ anilistId, video })`. Las URLs deben ser HTTPS y los IDs únicos.\n\n## Turbo.cr\n\nLa verificación técnica está en `docs/turbo-findings.md`. Con una URL real autorizada: `npx tsx scripts/probe-video.ts 'https://turbo.cr/....mp4'`. No se afirma compatibilidad con reproducción directa hasta ejecutar la prueba y la prueba manual en un móvil.\n\n## Arquitectura\n\n- `src/content/`: catálogo, helpers, validación y metadatos generados; sin UI ni red.\n- `src/services/`: cruce de catálogo + metadatos.\n- `scripts/`: Node; único lugar que habla con AniList.\n- `player/` será el único módulo que tocará `<video>` en los tickets posteriores.\n
